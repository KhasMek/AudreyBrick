# M3 task briefs: first build for the Brick

**Status: written 2026-11-17. M3-A started on the human's instruction to get it running on the Brick before the input path.**

M3 outcome: a Port folder the human copies to the SD card, which launches from KNULLI's Ports menu, plays, shows the screen, exits cleanly and leaves a log we can read.

Facts this builds on: `docs/PLATFORM_NOTES.md` section 10 (read from the firmware image the human runs: glibc 2.39, GCC 13 libstdc++, SDL 2.32.8 with only the `alsa` audio and `mali` video drivers, PipeWire behind ALSA at 48 kHz S16, Ports started with `/bin/bash <script>` and `SDL_GAMECONTROLLERCONFIG` already set, PortMaster not preinstalled, idle watcher dims and mutes after 300 s).

M3 is two tasks: **M3-A** builds and packages; then the human runs the first-run checklist; **M3-B** is whatever the log and the human's report show is needed (buffer size, button mapping, idle handling, text size).

Rules for every task: do not run any git command that changes state (the human commits); do not edit `docs/**`, `CLAUDE.md`, `third_party/**`, `src/shim`, `src/core`; our files start with `// Copyright (c) 2026 KhasMek` and `// SPDX-License-Identifier: MIT` (shell and CMake files: a `#` comment with the same two lines); each file includes what it uses; every target that includes DSP headers applies `${AB_DSP_OPT_OPTIONS}` and `${AB_WARNING_OPTIONS}`; our code compiles warning-free with clang and gcc; nothing is logged, allocated or locked on the audio thread. If a constraint cannot be met or something is ambiguous, stop and report.

## M3-A: device build, device behaviour and the Port package

```
Goal: One command produces a Port folder for the TrimUI Brick on KNULLI Scarab that starts
      fullscreen, plays, exits on the system hotkey, and writes a diagnostic log.

Context: M1 and M2 are complete. `audreybrick` runs on macOS. The Linux check so far
      (scripts/build_linux_arm64.sh, Debian 13, glibc 2.41, no SDL) is a portability test
      only and its binaries are too new for the device. A copy of the device's system
      image (squashfs) is available on this machine at the path the orchestrator gives
      you; it is not part of the repo and must not be copied into it.

Scope:
  - docker/Dockerfile.arm64-device, scripts/build_device.sh, scripts/package_port.sh,
    scripts/test_on_knulli_rootfs.sh
  - packaging/** (the launcher script template, the README shipped in the package)
  - src/app/App.{h,cpp}, src/app/main.cpp, new files in src/app/ for the pieces below
  - src/platform/** where the device needs it, src/ui/Renderer.{h,cpp} for renderer
    reset handling
  - tests/platform/**, tests/ui/** additions; CMake lines; .gitignore (dist/)
Out of scope: src/core, src/control, the engine, audio input, presets, the INPUT/MOD/
      PRESETS tabs, the safety limiter, PortMaster metadata (port.json, gameinfo.xml),
      any change to how parameters are displayed or mapped.

What to build:
  A. Device build. A Debian 12 (bookworm) arm64 image pinned by digest with g++, cmake,
     ninja and libsdl2-dev. scripts/build_device.sh mounts the repo read-only, builds
     Release in a container-local directory, runs the SDL-free tests and the SDL tests
     with dummy drivers, and copies out: the `audreybrick` executable and
     `libaudrey_lgpl.so`. The executable finds the library through an rpath of
     `$ORIGIN/libs.aarch64` (and the launcher also sets LD_LIBRARY_PATH). SDL2 is linked
     dynamically by soname (`libSDL2-2.0.so.0`); do not bundle SDL. libstdc++ and libgcc
     are linked dynamically. The script then checks the two binaries with objdump/readelf
     and FAILS if any needed symbol version exceeds GLIBC_2.39, GLIBCXX_3.4.32 or
     CXXABI_1.3.14, printing the highest versions found and the NEEDED list.
  B. Run it against the real system libraries. scripts/test_on_knulli_rootfs.sh takes the
     path of the device squashfs (or an already extracted root), extracts what is needed
     into a directory outside the repo, and runs the device build's `audreybrick` in an
     arm64 container whose root filesystem is the device's (for example `docker import`
     of the extracted tree, or a bind-mounted chroot), so the binary loads the device's
     own glibc, libstdc++ and libSDL2 2.32.8. It runs `--selftest tests/platform/rise.txt
     --seconds 5` with SDL_AUDIODRIVER=dummy and SDL_VIDEODRIVER=dummy (the device's SDL
     has both) and reports the result, `ldd` output from the device's own ldd, and the
     SDL version the app logs at run time. This cannot test the Mali display or ALSA
     output; say so in its output. Nothing from the image is executed other than the
     dynamic loader, libraries and standard tools needed for this.
  C. Device behaviour in the app:
     1. `--fullscreen`: SDL_WINDOW_FULLSCREEN_DESKTOP (or what the Mali driver needs),
        cursor hidden, logical size 1024x768 with integer scaling. On the device the
        screen is exactly 1024x768. Without the flag the app behaves as now.
     2. Quit paths: SDL_QUIT; Alt+F4 as a key event (KNULLI's exit hotkey for shell
        ports); Escape (already); and **Start + Select held together for 1 second** as a
        built-in fallback that works with no keyboard. While that combination is being
        held the screen shows "HOLD TO QUIT" clearly. The Select and Start presses still
        reach the control model as before (Select = fine); do not break fine adjust. The
        hold logic is SDL-free and unit-tested with synthetic time.
     3. A diagnostic log, `--log <file>`, written only from the UI thread, line-buffered
        so it survives a crash or power-off: app version (git describe passed in at build
        time, or "unknown"), build date and compiler; SDL compiled and linked versions;
        video driver, renderer name and flags, display mode, window and output sizes;
        audio driver, obtained spec; every controller added or removed with its name,
        GUID and the mapping string SDL uses; the FIRST time each Button is seen, with the
        SDL event that produced it (so we learn which physical button SDL calls A, and
        whether L2/R2 arrive as buttons or trigger axes); any SDL key event whose scancode
        we do not map (rate-limited; this reveals what Menu, Fn and the hotkey send);
        every 10 seconds one line with smoothed and maximum callback CPU, the largest
        callback buffer seen, output peaks, dropped commands and frames drawn per second;
        focus gained/lost; the reason for exit. No per-frame lines. The log path's
        directory is created if missing; failure to open the log is reported once on
        stderr and is not fatal.
     4. Renderer robustness: handle SDL_RENDER_TARGETS_RESET and SDL_RENDER_DEVICE_RESET
        by rebuilding the glyph atlas; if the renderer has no vsync, cap the frame rate at
        60; if texture creation fails the app keeps running and logs it.
     5. `--buffer` keeps working; the launcher passes a value from an environment
        variable so the human can try sizes without rebuilding.
  D. The package. scripts/package_port.sh assembles, outside the source tree under
     `dist/` (git-ignored):
        dist/AudreyBrick/AudreyBrick.sh
        dist/AudreyBrick/audreybrick/audreybrick            (executable)
        dist/AudreyBrick/audreybrick/libs.aarch64/libaudrey_lgpl.so
        dist/AudreyBrick/audreybrick/licenses/…             (every licence text)
        dist/AudreyBrick/audreybrick/THIRD_PARTY.md, LICENSE, README.txt
        dist/AudreyBrick/audreybrick/data/                  (logs; later presets, input files)
     plus `dist/AudreyBrick-<version>.zip` of that folder. The launcher is a
     self-contained bash script: no PortMaster, no control.txt, no gptokeyb. It resolves
     its own directory (it is started as `/bin/bash /userdata/roms/ports/AudreyBrick.sh`),
     sets LD_LIBRARY_PATH to libs.aarch64, keeps any SDL_GAMECONTROLLERCONFIG the system
     set, runs the binary with `--fullscreen --log data/audreybrick.log` and a buffer size
     from `AUDREY_BUFFER` (default 256), rotates the previous log to `.1`, captures stdout
     and stderr to `data/stdout.log`, and returns the binary's exit status. It must work
     on FAT/exFAT (no symlinks, no reliance on the executable bit surviving: invoke the
     binary so that a missing x bit does not break it, for example copy to /tmp and chmod,
     or run it through the dynamic loader; choose one, explain it, and test it in the
     rootfs container with the bit removed). README.txt: what this is, credits (Audrey II
     by Synthux Academy; Nick Donaldson, Infrasonic Audio; Roey Tsemah; link to the
     original repository), the button scheme, how to quit, where the log is, the note
     that `libaudrey_lgpl.so` contains ReverbSc and Tone under LGPL-2.1 and may be
     replaced with a rebuilt one, and where the source is (placeholder URL text "source
     repository: to be published" since the repo is not public yet). No Synthux or
     Infrasonic logos or artwork.

Constraints:
  - No file from the firmware image goes into the repo or the package.
  - The package contains no test tools, no reference audio, no docs/ directory.
  - The app must still build and pass everything on macOS and in the existing Debian 13
    check; the device build must not weaken AB_DSP_OPT_OPTIONS.
  - Nothing newer than SDL 2.0.18 API in non-test code (the device has 2.32.8; the build
    container has 2.26).
  - All logging is on the UI thread through values the audio thread already publishes.

Acceptance criteria:
  1. scripts/build_device.sh exits 0 and prints the symbol-version check with highest
     GLIBC <= 2.39 and GLIBCXX <= 3.4.32 for both binaries; it exits non-zero if the check
     is made to fail (demonstrate with a temporary stricter limit, not by changing code).
  2. scripts/test_on_knulli_rootfs.sh exits 0: the binary loads against the device's
     libraries, logs SDL 2.32.8 as the linked version, and the selftest passes; also with
     the executable bit removed from the packaged binary, launched through the packaged
     AudreyBrick.sh inside that root (dummy drivers set in the environment).
  3. scripts/package_port.sh produces the layout above and the zip; a listing is printed;
     every licence text in licenses/ of the repo is present in the package.
  4. Unit tests: the Start+Select hold-to-quit logic (not triggered by either button
     alone, by a short press, or by releasing and re-pressing; triggered at 1 s; Select
     still acts as fine); log line formatting; first-seen Button logging; frame cap.
  5. A selftest run with `--log` produces a log containing every item listed in C.3 that
     applies under dummy drivers; a screenshot test shows the "HOLD TO QUIT" overlay
     without overlapping other text.
  6. All existing verification still passes: Release, ASan/UBSan, TSan (control,
     platform, ui), no-SDL, scripts/verify_vendor.sh, scripts/make_reference.sh --check,
     scripts/build_linux_arm64.sh, the dummy-driver selftest on macOS.

How to verify: the commands named above, from clean build directories.

Report back: files added and changed; the base image digest and tool versions; the
  symbol-version table; the rootfs test output; the package listing and zip size; test
  summaries for every build; what the launcher does about the executable bit and why;
  anything about the Mali video driver you could determine from the device's libSDL2
  (for example which window flags or hints it needs) and what remains a guess;
  deviations; open questions; and a numbered first-run checklist for the human (copying
  to the SD card, where Ports live, refreshing the game list, launching, what to try,
  how to quit, how to retrieve data/audreybrick.log).
```
