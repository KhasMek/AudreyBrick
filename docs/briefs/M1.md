M1 outcome: the DSP builds and runs on the Mac without libDaisy and renders reference WAVs from scripted parameters.

**M1-A is done and reviewed (2026-11-17).** What it left for the later tasks: link `audrey_dsp` to get the include paths and both libraries; apply `${AB_DSP_OPT_OPTIONS}` and `${AB_WARNING_OPTIONS}` to every new target that compiles DSP code (see the comments in the root `CMakeLists.txt`); `scripts/verify_vendor.sh` fails on any file under `third_party/` or `licenses/` that is not in its manifest, so a task that adds a vendored file (dr_wav in M1-C) must add it to that manifest.

**M1-B is done and reviewed (2026-11-17).** What it left for M1-C: the static library `audrey_core` (link it; it brings `audrey_dsp`); `audreybrick::AudreyVoice` in `src/core/AudreyVoice.h`; `audreybrick::ScriptControlSource` in `src/control/ScriptControlSource.h`, whose header documents the script format. Knob names in scripts are the firmware enum names (`Frequency`, `FeedbackGain`, ... , matched case-insensitively) plus `switch`. Numbers must be written as `0.5`, not `.5`. `ScriptControlSource::events()` exposes the parsed events, which the render tool can use to warn about events scheduled after the end of a render. Any target that includes `AudreyVoice.h` or `ScriptControlSource.h` compiles upstream inline DSP and must apply `${AB_DSP_OPT_OPTIONS}`. The reviewer noted that no test inside the repo yet pins `AudreyVoice` to an upstream transcription (a swapped pair of engine handlers would pass every M1-B test); **M1-C's parity test must close this**, so its reference harness must bind each parameter to its engine setter by reading the upstream file, not by copying `AudreyVoice.cpp`.

Order: **M1-A, then M1-B, then M1-C.** M1-D is optional (decision D5) and can run after M1-A. Each task has one implementer and is followed by a review using the review brief at the end. No two tasks touch the same files.

Every worker reads first: `CLAUDE.md`, `docs/PLATFORM_NOTES.md` sections 4, 6 and 8, `docs/PLAN.md`, `docs/SIGNAL_FLOW.md`, `docs/PARAMETERS.md`.

## M1-A: vendoring and build skeleton

```
Goal: The original Audrey II DSP sources and the DaisySP modules they need are vendored
      unmodified, and build into static libraries on macOS with CMake, with no libDaisy and no SDL.

Context: The repo currently has only docs. docs/PLAN.md sections 2, 3 and 5 define the layout,
      the shim headers and the build flags. docs/SOURCE_STUDY.md section 2 explains the licence
      situation. The orchestrator will tell you the outcome of decision D1 (how reverbsc and
      tone are built: separate shared library, or static). Do not start without it.

Scope: CMakeLists.txt (root), third_party/**, src/shim/**, licenses/**, THIRD_PARTY.md,
      tests/smoke/**, .gitignore.
Out of scope: src/core, src/control, src/tools, src/platform, docs/** (report doc changes
      you think are needed; do not make them), anything SDL.

Constraints:
  - Files under third_party/audrey-ii/Source and third_party/daisysp*/Source must be
    byte-identical to the pinned upstream commits. No edits, no reformatting. If something
    does not compile, stop and report; do not patch.
  - Vendor only the files listed in docs/PLAN.md section 3. Do not vendor
    FeedbackSynthControls.*, Source/memory/*, FeedbackSynth_main.cpp, the Makefile,
    .vscode, doc/ images, or any libDaisy file.
  - Do not copy any image, logo or panel artwork.
  - third_party/audrey-ii must contain: LICENSE (official repo, "Copyright (c) 2026 Synthux
    Academy"), LICENSE.archive-2022 (archive copy, "Copyright (c) 2022 Infrasonic Audio, LLC"),
    CREDITS.md, and UPSTREAM.md recording URL, commit, date fetched and the file list.
  - reverbsc.{h,cpp} and tone.{h,cpp} go in third_party/daisysp-lgpl/, taken from DaisySP
    7f67768, with the LGPL-2.1 text and a note explaining their provenance.
  - src/shim/memory/sdram_alloc.h provides namespace infrasonic, class SDRAM with
    template<typename T, class... Args> static T* allocate(Args&&...) implemented with a
    plain new-expression. It must be found before any upstream path for the include
    "memory/sdram_alloc.h".
  - src/shim/daisysp.h includes only the nine modules listed in docs/SIGNAL_FLOW.md section 2.
  - C++17, no extensions. DSP targets: -O2 -fwrapv. Never -ffast-math. Warnings off for
    third_party only.
  - No new dependency beyond those named here.

Acceptance criteria:
  1. cmake configure, build and ctest succeed from a clean checkout on macOS arm64.
  2. Targets audrey_dsp and audrey_lgpl exist as described in docs/PLAN.md section 5.
  3. A smoke test constructs infrasonic::FeedbackSynth::Engine, calls Init(48000), sets all
     eleven parameters through the Engine setters, processes 5 seconds with feedback gain at
     +6 dB, and asserts: every output sample is finite, and the output is not all zeros.
     A second case with feedback at -60 dB asserts the output peak is below 0.001.
  4. Creating and destroying the Engine 20 times in one process does not crash or leak
     (run the smoke test under AddressSanitizer in a separate build directory).
  5. A script scripts/verify_vendor.sh re-fetches the pinned commits into a temp directory
     and diffs every vendored file; it exits 0 only if all are identical.
  6. THIRD_PARTY.md lists each vendored component with licence, copyright line, source URL,
     commit, and the list of files. licenses/ holds every licence text.

How to verify:
  cmake -S . -B build/host -DCMAKE_BUILD_TYPE=Release && cmake --build build/host -j
  ctest --test-dir build/host --output-on-failure          -> all tests pass
  cmake -S . -B build/asan -DCMAKE_BUILD_TYPE=Debug -DCMAKE_CXX_FLAGS="-fsanitize=address,undefined -fno-sanitize=signed-integer-overflow"
  cmake --build build/asan -j && ctest --test-dir build/asan --output-on-failure   -> pass, no reports
  scripts/verify_vendor.sh                                 -> exit 0

Report back: files added, the exact upstream commits fetched, full output of the four
  commands above, any upstream file that needed a compiler flag to build, any place the
  brief could not be followed, and open questions.
```

## M1-B: control abstraction and voice wrapper

```
Goal: A hardware-free AudreyVoice reproduces the firmware's audio callback exactly, driven
      by a ControlSource that supplies normalised knob values.

Context: M1-A is merged: audrey_dsp and audrey_lgpl build, and the upstream ParameterRegistry
      and Engine are available. The interfaces are specified in docs/PLAN.md sections 3 and 4
      and must be implemented as written. The firmware behaviour to reproduce is in
      docs/PARAMETERS.md sections 1 and 2 and docs/SIGNAL_FLOW.md section 1 (step 9).
      For the exact original logic, read FeedbackSynthControls.cpp and FeedbackSynth_main.cpp
      at upstream commit e5ab799 (not vendored; fetch to a temp directory to read).

Scope: src/core/**, src/control/ScriptControlSource.{h,cpp}, tests/core/**, and the CMake
      lines that add them.
Out of scope: third_party/**, src/shim/**, src/tools/**, tests/ref/**, scripts/**, docs/**.

Constraints:
  - AudreyVoice::process and every ControlSource::read must not allocate, lock, log, do I/O
    or wait. init() may allocate.
  - The engine runs at 48000 Hz with control blocks of exactly 4 samples, counted across
    process() calls of any length, including lengths that are not multiples of 4.
  - Per control block, in this order: read ControlFrame; UpdateNormalized for the eleven
    parameters with the same ranges, curves, smoothing times and initial values as upstream
    registerParams; ReverbDecay is first shaped with ftension(x, -3.0f); EchoDelayTime is
    multiplied by 0.5 when the switch is on, before mapping; params.Process(); 4 samples of
    Engine::Process(in, outL, outR); then daisysp::Limiter::ProcessBlock(buf, 4, 0.7f) on
    each channel.
  - ControlFrame values are used as given (they already represent 1 - adc). Do not add
    smoothing, dead zones, clamping beyond what ParameterRegistry does, or any feature.
  - inMono == nullptr means silence. A non-finite input sample is replaced by 0 before the
    engine (this is the one deliberate addition; document it in the header).
  - Code transcribed from FeedbackSynthControls.cpp carries the upstream MIT notice with both
    copyright lines in a comment at the top of the file.
  - ParamTable holds, per knob: panel name, unit, min, max, curve, smoothing time, default
    (docs/PARAMETERS.md section 4), and a function mapping a normalised value to the engine
    value for display. It is the single place those numbers appear in our code.
  - ScriptControlSource: loads a text script before audio starts. Line format:
    "<time_seconds> <knob-name|switch> <value> [ramp_seconds]", '#' comments. Values ramp
    linearly. It advances one control block per read() and is deterministic.

Acceptance criteria:
  1. Unit tests cover: mapping of each knob at n = 0, 0.5 and 1 against the values in
     docs/PARAMETERS.md; the reverb-decay shaping at 0.25, 0.5, 0.75; the switch scaling
     (n = 1 gives 5.0 s off and 1.2875 s on); control-block alignment when process() is
     called with frame counts 1, 3, 4, 7, 64 and 257 (output identical to a single call);
     nullptr input; NaN input does not propagate.
  2. With all knobs at their defaults, 10 seconds of output has peak below 0.001.
  3. With feedback at 1.0 and every other knob at 0, 0.5 and 1.0 in turn (three runs),
     30 seconds of output is finite throughout.
  4. A test that fails if process() allocates (override global operator new in the test
     binary and count calls during process()).
  5. All tests pass under AddressSanitizer and UndefinedBehaviorSanitizer.

How to verify:
  cmake --build build/host -j && ctest --test-dir build/host --output-on-failure
  cmake --build build/asan -j && ctest --test-dir build/asan --output-on-failure
  Passing = every test passes in both, with no sanitizer report.

Report back: files changed, full test output from both builds, any place where the upstream
  logic was ambiguous and how you read it, and open questions.
```

## M1-C: render tool, parity test and reference set

```
Goal: A command-line renderer produces WAV files from parameter scripts, a checker inspects
      them, the port is proven sample-identical to an independent harness around the upstream
      engine, and a reference set is committed.

Context: M1-A and M1-B are merged. docs/PLAN.md section 6 defines the verification approach
      and the script list. AudreyVoice and ScriptControlSource exist in src/core and
      src/control; use them, do not change them.

Scope: src/tools/**, tests/ref/**, tests/parity/**, scripts/*.txt, scripts/make_reference.sh,
      reference/**, third_party/dr_libs/**, the THIRD_PARTY.md entry and licence file for
      dr_wav, the dr_wav entries in scripts/verify_vendor.sh's manifest, and the CMake lines
      that add these.
Out of scope: src/core/**, src/control/**, src/shim/**, third_party/audrey-ii,
      third_party/daisysp*, docs/**.

Constraints:
  - tests/ref/ is a reference harness written directly against the upstream Engine and
    ParameterRegistry, following FeedbackSynth_main.cpp and FeedbackSynthControls.cpp at
    commit e5ab799. It must not include or link anything from src/core. It may reuse
    ScriptControlSource only for parsing the script.
  - audrey-render: arguments are a script path, an output WAV path, a duration, and an
    optional mono input WAV (must be 48 kHz; reject otherwise). Output: 48 kHz stereo,
    32-bit float WAV.
  - wavcheck prints and returns non-zero on: any NaN or inf; absolute DC offset above 0.001
    on either channel; absolute peak above 1.0. It also reports peak, RMS, and the count of
    sample-to-sample jumps above a threshold given on the command line.
  - Scripts to write, each with a comment header saying what it shows: silence at minimum
    feedback; slow feedback rise from minimum to maximum over 30 s; one script per knob
    sweeping it over 20 s with feedback at a setting that sustains a drone; the switch
    toggled four times during a long echo; echo feedback held at maximum for 30 s; all knobs
    at minimum; all knobs at maximum; input sine burst with feedback at minimum; input noise
    burst with feedback raised. Generate the two input WAVs with a small tool or script that
    is committed, not by hand.
  - reference/ holds the rendered WAVs if the set is under 60 MB in total, otherwise only
    reference/SHA256SUMS; say which in the report. reference/README.md records the compiler
    version and flags used.
  - dr_wav is the only new dependency. Record its commit and licence.

Acceptance criteria:
  1. For every script, the parity test shows AudreyVoice output is identical, sample for
     sample, to the reference harness output (compare the float bits).
  2. Every reference render passes wavcheck, except that renders designed to saturate may
     set a higher jump threshold, stated in the script header.
  3. scripts/make_reference.sh regenerates the set and the hashes match on a second run.
  4. The minimum-feedback render has peak below 0.001. The feedback-rise render exceeds
     peak 0.05 before its end.

How to verify:
  cmake --build build/host -j && ctest --test-dir build/host --output-on-failure   -> all pass
  scripts/make_reference.sh && (cd reference && shasum -a 256 -c SHA256SUMS)       -> all OK
  build/host/wavcheck reference/<each>.wav                                         -> exit 0

Report back: files changed, full ctest output, the wavcheck line for every render, total
  size of reference/, render speed relative to real time, anything in a render that looks
  or measures wrong (clicks at parameter changes, DC, unexpected silence), and open questions.
```
